### Документ и контекст

Результат представлен документным [Bundle](StructureDefinition-semd-amb-bundle.html). Первым ресурсом является [Composition консультации](StructureDefinition-semd-amb-composition.html); разделы Composition сохраняют содержание и порядок разделов источника и ссылаются на клинические ресурсы. В проверенном примере 20 разделов и 78 ресурсов внутри Bundle.

| Сведения СЭМД | Представление FHIR |
|---|---|
| Заголовок, тип, дата, автор, заверитель, организация-хранитель | Composition |
| Идентификатор документа `.50`, версия документа | Composition.identifier, Composition.version |
| Идентификатор экземпляра документа `.51` | Bundle.identifier |
| Пациент, удостоверяющие сведения, адреса и контакты | Patient |
| Медицинские организации и подразделения | Organization, связи между организациями |
| Медицинские работники и их роли | Practitioner, PractitionerRole |
| Посещение консультации, условия и период | Encounter |
| Тип и номер амбулаторной карты | Логическая ссылка Encounter.partOf; [правило без system](conventions.html) |
| Сведения страхового покрытия | Coverage |

Контекстные UUID ресурсов не заменяют исходные бизнес-идентификаторы. Локальные ключи записей `.52` используются для разрешения внутренних ссылок и определения идентичности записи в контексте документа; они не превращаются в глобальные идентификаторы. Разные исходные документы не объединяются по совпадению локального XPath или одного неоднозначного реквизита.

### Клинические сведения

| Сведения источника | Представление и существенное правило |
|---|---|
| Диагнозы DGN | Condition и Encounter.diagnosis; контейнер 838 раскрывается в отдельные заболевания |
| Роль диагноза и обоснованность | Сохраняются как разные смысловые оси; основной диагноз не подменяет подтверждённость |
| Жалобы, анамнез, осмотр, показатели, результаты, инвалидность | Observation с исходными кодами, значениями, датами и уточнениями |
| Расчётная шкала и явно кодированные входные данные | Observation.derivedFrom для входов расчёта |
| Ссылки результатов RESCONS/RESLAB/RESINSTR на LINKDOCS | Observation.derivedFrom → соответствующий DocumentReference |
| Аллергологические сведения ALL | AllergyIntolerance; текст аллергена, тип реакции и проявление сохраняются отдельно |
| Выполненные услуги SERVICES | Procedure с кодом и датой услуги; участники добавляются только при наличии в источнике |
| Применение Диаскинтеста IMM | MedicationAdministration; без Encounter консультации |
| Сообщённое лекарственное лечение DRUG | MedicationStatement и Medication; дозировка, расписание, путь и условия приёма |
| Рекомендации и режим | CarePlan и исходный текст; назначения из свободного текста не выводятся |
| Связанные документы LINKDOCS | DocumentReference, реквизиты и дата формирования; отсутствующий файл не выдумывается |

Общие квалификаторы наблюдений в проверенном прототипе могут представляться связанными Observation через hasMember. Это сохраняет структуру проверенного примера, но не определяет универсальную модель для всех клинических отношений CDA. Специальное правило derivedFrom применяется к явно установленным входам расчёта и ссылкам результатов на документы.

### Время, значения и неопределённость

Сохраняются исходные число, единица, точность даты и заданный часовой пояс. Дата без времени не дополняется временем суток; неизвестное время не заменяется моментом преобразования. В расписании 12 h представляется как период 12 с periodUnit=h. Преобразование избранных кодов единиц времени не означает поддержки всех кодов и редакций НСИ.

Кодирования содержат system, code, display и version в пределах сообщённого источником. Уже выраженный клинический смысл не дублируется только ради переноса каждого технического атрибута. Исходная версия справочника, если сообщена, сохраняется; неизвестная версия не угадывается.

Отсутствие данных и явное значение nullFlavor различаются. Для бесконечной верхней границы периода PINF сохраняется соответствующий iso21090-nullFlavor; она не заменяется unknown. Статус Observation=unknown отражает отсутствие установленного статуса в источнике. Coverage=draft и DocumentReference=current описывают создаваемые записи и не подтверждают действительность полиса или клинический статус связанного документа.

Подробные соглашения о роли участника услуги, документных датах, медицинской карте, препарате и дозе приведены на [отдельной странице](conventions.html).
